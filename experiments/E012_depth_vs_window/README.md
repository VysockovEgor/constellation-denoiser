# E012 — Глубина и ширина против окна

## Вопрос
Слияние линейных слоёв подтвердило, что «Керр только после 2-го слоя» (`a`)
выразительно эквивалентен одному скрытому слою. Однако при 20k шагах вариант
`a` даёт 62.2 %, а один скрытый слой, обученный напрямую, — 59.4 %
(`experiments/E009_kerr_ablation/results/complex_mlp_ablation_summary.csv`).
Это может быть разница в динамике оптимизации, а не в выразительности.
Возвращает ли второй слой преимущество при окнах 65 и 127 и при длинном обучении?

## Правило интерпретации (до запуска) — ЧЕРНОВИК
Статус: черновик, пользователь подтверждает его до первого запуска; после
просмотра результатов не меняется. Копия в `config.json` → `rule_draft`.

- Второй слой **«возвращает преимущество»** для окна W, если при том же бюджете
  шагов `v1` или `v2` выше и `v3`, и `v4` по среднему тестовому снижению BER
  более чем на разброс seeds и не менее чем на 0.5 п.п.
- Если разрыв `v2 − v3` при 20k больше разброса seeds, а при 100k меньше
  разброса, это трактуется как **эффект оптимизации**, а не выразительности.
- Иначе — «не доказано».

Метрика сравнения — тест в точке лучшей валидации
(`test_reduction_valbest_select`; замер каждые 1000 шагов при 20k и каждые
5000 при 100k). Разброс seeds — размах (max − min); берётся больший из двух
сравниваемых групп. Тест не используется для выбора.

## Варианты (hidden 48, если не сказано иное)
| вариант | модель | умножений W=31 / 65 / 127 |
|---|---|---|
| `v1_two_kerr_both` | два слоя, Керр на обоих (`PaperComplexMLP`) | 16 032 / 22 560 / 34 464 |
| `v2_two_kerr_last` | два слоя, Керр после 2-го (`AblationComplexMLP` a); до слияния | 15 696 / 22 224 / 34 128 |
| — после слияния | | 6 480 / 13 008 / 24 912 |
| `v3_one_hidden` | один скрытый слой 48 с Керром | 6 480 / 13 008 / 24 912 |
| `v4_one_hidden_wide` | один скрытый слой с Керром, ширина 119 / 83 / 66 | 16 065 / 22 493 / 34 254 |

Ширина `v4` — ближайшее целое к решению h·(4W+11) = 4·48·(W+48+1) + 14·48
(формулы ЧАСТИ 0, `model_zoo.width_matching_macs`).

## Протокол
- Окна {31, 65, 127} × 4 варианта × шагов {20k, 100k} × seeds {17, 29, 43}.
  20k и 100k — отдельные прогоны (свой горизонт затухания для ветки `best_e010`).
- 30 train-файлов, 45 validation и 45 test (split E007–E009). Adam, batch 1024,
  complex MSE, Glorot, `c` = 0.
- Ветки lr: `const_1e-3`; `best_e010` (необязательная) из
  `experiments/E010_lr_schedule_study/results/stage1_selection.json`:
  `v1` ← `both`, `v2`/`v3`/`v4` ← `a`. Без файла стадия `best` пропускается.
- **Проверка слияния:** для `v2` при каждом окне, бюджете и seed слитая модель
  (`MergedAblationMLP`) сравнивается с исходной на первых 1000 train-окнах
  (веса на последнем шаге), допуск макс. абсолютного отличия < 1e-4 (float32) →
  `results/merge_check.csv`, как в E009.

## Стадии и число прогонов
| стадия | что | прогонов |
|---|---|---|
| `control` | `v1`, `v2`, `v3` при W=31, 20k, const, seeds 17 и 29 | 6 (входят в `const`) |
| `const` | вся сетка, const 1e-3 | 72 (66 новых после `control`) |
| `best` | вся сетка, `best_e010` | 72 (если есть выбор E010) |

Всего около 4.3 млн шагов на ветку. Контроль (±0.7 п.п. по среднему seeds 17 и
29): `v1` 61.727 % (E007), `v2` 62.191 % и `v3` 59.437 % (E009, варианты a и d).
Для окон 65 и 127 есть только справочные числа E007 для `v1` (58.378 % и
52.672 %; у 127 размах seeds 49.6–55.8), допуском они не проверяются.

## Оценка времени
Печатает `run.sh plan all` на сервере. Окно 127 примерно вчетверо дороже окна
31 на шаг; прогоны 100k составляют ~80 % шагов. Локальный smoke даёт только
порядок величины.
