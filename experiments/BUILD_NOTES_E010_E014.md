## Итог разведки

**Данные и split.** `data/raw/archive/` — 2000 CSV (PR1–PR2000), 16 384 строки
`tx_I, tx_Q, rx_I, rx_Q`, ~860 КБ каждый, всего 1.7 ГБ; 1356 уникальных по
SHA-256 (`data/manifest/data_audit_all.csv`, `get_unique_files`). E007–E009
берут split из `experiments/E004_training_file_curve/config.json`:
`train_pool_files[:30]` + 45 validation + 45 test. Пул из 210 файлов совпадает
как множество с `train_files` E003, validation/test идентичны (проверено).
Манифест в config E001–E009: `data_manifest_sha256 = cb5f2de…` — это SHA-256
`data/manifest/pre_migration_sha256.txt`. Raw BER считается прямо по `rx`
(данные уже после восстановления фазы; отдельного шага в коде нет).

**Умножения.** `complex_mlp_ablation.complexity()`; 4 на комплексное умножение,
7 на нейрон Керра; формулы промпта совпали: 16 032 (`both`, W=31, h=48) и
6 480 (после слияния / один слой). Для варианта `a` до слияния — 15 696.
Варианты E009: `baseline` (Керр на обоих), `a` (только после 2-го), `b`
(только после 1-го), `c` (без Керра), `d` (один скрытый слой). `c` хранится
**по одному на слой** (`NonlinearPhase.c`, скаляр), не на нейрон.

**Числа контроля** — тест в точке лучшей валидации среди шагов, кратных 1000
(`summarize_complex_mlp_ablation.load_ablation_rows`), а не финальный шаг: для
`a` финал 20k даёт 61.38 % против 62.19 % по лучшей валидации. Поэтому допуск
проверяется по `test_reduction_valbest_select` (select_every=1000).

**Launcher'ы E007–E009.** Bash-циклы с фиксированными `--threads 6` или
`JOBS=8`, логи через `>>`, без `trap`; в E009 `c/seed17` завершился с ошибкой,
но строки CSV есть (дозапись после resume, дубликаты в CSV), PID-файл остался
от прошлого запуска. Новый раннер: JSON на прогон атомарно, пропуск готовых,
PID-файл удаляется в `trap`, живой PID блокирует повторный запуск.

**Окружение.** Рабочий интерпретатор — `.venv/bin/python` (torch 2.14.0, scipy
есть); `~/.virtualenvs/constellation-denoiser` без scipy. `run.sh` берёт
`.venv`, если он есть, иначе `python3` или `PYTHON=...`.

## Расхождения промпта с репозиторием

1. E001 не содержит `real_tanh`: там MLP с ReLU, CNN, LSTM, Transformer, окно 7,
   split PR1–7/8/9–10. Реальная tanh-MLP — E002/E003/E005 (`WindowMLP`, tanh, Xavier).
2. Трансформер E001 (`models.TransformerEqualizer`): FFN = 2·d (не 4·d),
   pre-norm, обучаемые позиционные эмбеддинги, голова LayerNorm → Linear(d,d) →
   GELU → Linear(d,2), AdamW wd 1e-5. Подсчёт умножений делается для реальной
   архитектуры (FFN 2d, голова d²+2d); формула промпта с 4d отличается — описать в E013.
3. Реальная сеть «вдвое больше нейронов»: hidden 96 → 2W·h + h² + 2h = 15 360 =
   плотная часть комплексной `both` (без 7 на нейрон Керра).
4. Данные материализуются в старом коде (`collect`); новый `window_data.py`
   режет окна на лету, порядок индексов совпадает с `collect` (проверено
   побитово: окна, центры, raw BER, BER модели, диагностика шага 0 E009).

## Общие решения (части 0–1)

- `src/constellation_denoiser/`: `window_data.py` (окна на лету, кэш `.npy` в
  `data/cache/`, вне Git), `lr_schedules.py`, `model_zoo.py` (реестр моделей и
  умножений поверх старых классов), `runner.py` (очередь, вежливый режим,
  чекпоинты >20k, фазы обучения, контроль), `grids.py` (задачи из config.json),
  `resources.py` + `scripts/probe_resources.py`, `merge_runs.py`, `plot_style.py`.
- `scripts/run_common.sh` — общий код всех `run.sh`.
- Run id без имени стадии → совпадающие конфигурации переиспользуются.
- Продолжение после `kill -9` проверено: кривая совпадает побитово.
- Оценка на 45+45 файлах ≈ 10 с на точку (локально, 1 поток) → при eval каждые
  250 шагов это ~75 % времени E010; `TEST_EVERY=1000` безопасно сокращает.
- Smoke E010 (все стадии, 46 прогонов по 300 шагов): ~3 мин локально, JOBS=2.

## Решения части 2 (E011)

- Общие хелперы в `grids.py`: `best_e010_lr`, `lr_branches`, `control_tasks`
  (20k-контроли, `config.json` → `control.runs`/`targets`). Нужны и для E012–E014.
- В записи прогона появились `budget` (номинальный бюджет шагов) и
  `n_train_nominal` (заданное N): в smoke шаги и файлы обрезаются, а сводки
  группируют по номинальным значениям.
- Подгонка `y_inf` ограничена a ≥ 0, b ∈ [0.01, 5]: без этого на плоской кривой
  получалось бессмысленное `y_inf` с отрицательным `a`.
- Smoke E011 (control 2 + const 8 + best 6 прогонов): ~1.5 мин локально.

## Решения части 3 (E012)

- Ширины `v4` (ближайшее целое): 119 / 83 / 66 для W = 31 / 65 / 127.
- Контрольные задачи E012 — подмножество основной сетки (те же run id), поэтому
  после `control` стадия `const` их не пересчитывает.
- `summary_utils.compare`: «больше разброса seeds» = разность средних больше
  наибольшего размаха (max − min) двух групп и не меньше 0.5 п.п. Используется в E012–E014.
- Post-hook `merge_check` (`grids.POST_HOOKS`) пишет `merge_*` в JSON прогона.
- Smoke E012 (3 + 21 + 24 прогона): ~2.5 мин локально.
- Push из этой среды не проходит (нет учётных данных HTTPS); пользователь пушит сам.

## Решения части 4 (E013)

- Трансформер: `models.TransformerEqualizer` (E001) без изменений; в `model_zoo`
  `ffn_mult` ≠ 2 запрещён, чтобы подсчёт умножений совпадал с реальной сетью.
- Скорость локально (1 поток): W=31, d=64, L=2 — 1.6 шага/с и ~3.5 тыс. окон/с
  при оценке → валидация каждые 2000 (A) и 5000 (B), а не 1000.
- `resources.scaled_rates`: время ∝ (умножения/эталон)^0.7 (подгонка по
  замерам трансформера), вместо линейной формулы, сильно завышавшей малые модели.
- Вердикт сравнивает с E011 (кривая const на шагах 20k/100k, N=210); логика
  проверена на подставных данных. E003/E001 — только справочные точки.
- Smoke E013 (1 + 8 + 4 прогона): ~12 мин локально, в основном d=64, L=2. В smoke
  warmup 1000 > 300 шагов, поэтому низкие значения ожидаемы.

## Решения части 5 (E014)

- `kan.py`: KANLinear (SiLU + B-сплайн k=3, сетка [−2, 2]), KANNet, KANOnly,
  KerrKAN (parallel/cascade, нулевой последний слой KAN). Подсчёт операций:
  `kan_layer_cost` (плотно и разреженно).
- Фазы обучения в раннере: `trainable` (префиксы `kerr.`/`kan.`),
  `reset_optimizer`. Первая стадия k3/k4 совпадает с k0b побитово; `c` в стадии 2
  заморожен (проверено в smoke).
- Post-hook `kan_costs` пишет `kan_*`, `kerr_macs`, `macs_*_total` во все прогоны E014.
- Необязательный анализ остатка сделан (стадия `residual`, валидационные файлы).
- Smoke E014 (1 + 10 прогонов + сводка + residual): ~1 мин локально.
