# E017 — Физика + малая нейросеть на остаток

## Вопрос
Если физическая часть (PhysKerr из E016) берёт основную долю, сколько
нейросети нужно «на остаток»?

## Правило интерпретации (до запуска) — ЧЕРНОВИК
Статус: черновик, пользователь подтверждает его до первого запуска; после
просмотра результатов не меняется. Копия в `config.json` → `rule_draft`.

- Гибрид «**лучше при равной стоимости**». Среди гибридов (любые h и режим)
  не дороже 6 480 умножений (`complex_a` после слияния) по валидации
  выбирается один. Он должен быть выше на тесте и `complex_a` (этот
  эксперимент, 5 seeds), и выбранной по валидации конфигурации E016 —
  не менее чем на 1 п.п. и больше разброса seeds в обоих сравнениях.
- «**Нейросеть на остаток не нужна**», если при h = 4 и `frozen`, и `joint`
  отличаются от выбранной конфигурации E016 меньше, чем на разброс seeds.
- Режимы `frozen` и `joint` сравниваются между собой только как наблюдение
  (`results/frozen_vs_joint.csv`): это разные пути оптимизации, вердикта нет.
- Иначе — «не доказано».

Метрика — тест в точке лучшей валидации и Q²-прирост в ней; выбор только по
валидации; разброс — размах по seeds (больший из двух групп).

## Модель
`y = PhysKerr(z) + MLP_res(z)` (`phys_models.PhysPlusMLP`). MLP_res — один
скрытый комплексный слой h ∈ {4, 8, 16, 48} с активацией Керра, окно 31.
Выходной слой MLP_res стартует с нуля, поэтому гибрид в начале равен PhysKerr.

- **PhysKerr** — конфигурация (R, L, sym) с лучшей средней валидацией в
  `experiments/E016_phys_kerr_only/results/phys_kerr.csv`. Выбор
  записывается в `results/e016_choice.json` при построении стадии. Если E016
  ещё не считался — R = 7, L = 31, sym. Run id содержит R, L, sym, поэтому
  результаты для разных основ не смешиваются.
- **`frozen`**: PhysKerr обучается 20k шагов (MLP_res заморожен в нуле), затем
  замораживается, а MLP_res обучается 20k шагов со свежим оптимизатором.
- **`joint`**: оба блока с нуля, 40k шагов — тот же бюджет.
- **lr.** Берётся ветка, при которой выбранный PhysKerr был лучшим в E016
  (`const_1e-3`, `best_e010_cm1` или `best_e010_cm30`). Если E016 нет — по
  плану `best_e010` (`stage3_choice.json['a']`, `c_mult` 30), а без него —
  const 1e-3. **Отклонение от плана** («всегда best_e010»): в smoke E016
  `c_mult` 30 схлопывал часть PhysKerr, поэтому, когда есть выбор по
  валидации, используется он.
- **Умножения:** `macs_phys` основы + h·(4·31 + 11) = 135·h (один слой,
  сливать нечего). При h = 48 гибрид дороже 6 480 и в первый вердикт не входит.

## Сетка и контроли
- h {4, 8, 16, 48} × режим {frozen, joint} × seeds {17, 29, 43, 57, 71} =
  40 прогонов по 40k шагов; валидация каждые 1000, чекпоинты каждые 10k.
- Контроль (`control`): `complex_a` и `one_hidden` (h = 48), const 1e-3, 20k,
  5 seeds. Допуск ±0.7 п.п. по среднему seeds 17 и 29: 62.191 % и 59.437 %
  (E009). Если контроль не прошёл, `main` не запускается.

## Команды
```bash
bash experiments/E017_phys_plus_mlp/run.sh estimate all
bash experiments/E017_phys_plus_mlp/run.sh control
bash experiments/E017_phys_plus_mlp/run.sh main        # после E016 summarize
bash experiments/E017_phys_plus_mlp/run.sh summarize
SMOKE=1 bash experiments/E017_phys_plus_mlp/run.sh smoke
```

## Ограничения
Окно 31; один split; 30 train-файлов; основа выбрана по валидации E016,
поэтому от неё зависят все результаты. Если E016 не завершён, используется
запасная основа R = 7, L = 31, sym.
