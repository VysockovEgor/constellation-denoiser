# E034 — Триплеты: больше памяти и сжатие

**Вопрос.** Растёт ли качество T3 + КИХ дальше M = 21, и сколько членов-триплетов достаточно (RM против качества)?

**Правило (до запуска, черновик).** Рост с M продолжается, если T3 + КИХ7 при M = 31 − M = 21 (E031) ≥ 1 п.п.; K = 128 членов сохраняют ≥ 90 % снижения полной модели M = 25; сжатые триплеты лучше Kerr-сети при равных RM, если разница Q² ≥ 0.1 дБ и интервалы не пересекаются (проверка в E033). Полностью — `config.json` → `rule_draft`.

**Что делает** (`triplets_ext.py`, закрытая форма, как E031): T3 + КИХ7 при M ∈ {25, 31}; отбор: полная модель M = 25 на реплике (λ по валидации), члены ранжируются по |C_j|·rms(признака_j) на train, K ∈ {16, 32, 64, 128, 256, 512} сильнейших + 7 отводов КИХ переподбираются из подматрицы тех же нормальных уравнений, λ снова по валидации. RM (sym) = 12K + 28. 5 бутстреп-реплик файлов обучения.

**Команда.** `bash experiments/E034_triplets_extended/run.sh <стадия>`; стадии: main | fit | summarize | smoke. CPU, BLAS 16 потоков.

**Результаты.** `results/triplet_ext_summary.csv`, `triplet_ext_verdicts.csv`, `runs_table.csv`; рисунок `figures/E034_triplets_pruned_vs_rm.png`.
