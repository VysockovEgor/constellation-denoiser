# E019 — Длинные подтверждения (стадия `confirm` промпта E015–E018)

Это стадия `confirm` из ЧАСТИ 6 промпта E015–E018. Она вынесена в отдельную
папку с новым E-номером, потому что `AGENTS.md` требует нового номера и
отдельного пути для каждого нового запуска.

## Вопрос
Выходят ли лучшие по валидации модели E016, E017, E018 и контроли
`complex_a`, `complex_both` на плато за 100k–200k шагов? В E011 плато за 200k
шагов достигнуто не было.

## Правило интерпретации (до запуска) — ЧЕРНОВИК
Статус: черновик, пользователь подтверждает его до первого запуска; после
просмотра результатов не меняется.

- **Плато** — как в E011: прирост сглаженного (окно 10k) валидационного
  снижения BER за последние 50k шагов меньше 0.2 п.п.
- Если плато нет, пишется «плато не достигнуто за N шагов», а `y_inf`
  (подгонка `y = y_inf − a·steps^(−b)`) — только как грубая оценка.
- Результат 200k приводится рядом с 20k/40k той же конфигурации в её
  эксперименте; других вердиктов нет.

## Что считается
- **Участники.** По одному из E016 (`phys_kerr.csv`), E017 (`phys_plus_mlp.csv`)
  и E018 (`dbp_depth.csv`): конфигурация и ветка lr с лучшей средней
  `best_val_reduction`. Выбор пишется в `results/confirm_choice.json` при
  построении стадии; семейство без результатов пропускается с сообщением. К
  ним добавляются `complex_a` и `complex_both` (окно 31, hidden 48).
- **Длины.** Ветка `const_1e-3` — только прогон на 200k. Точка 100k берётся из
  его кривой: при постоянном lr первые 100k шагов совпадают с прогоном на 100k
  (побитовое совпадение проверено в тестах продолжения E010). Ветка
  `best_e010` к концу затухает, поэтому для неё 100k и 200k — отдельные прогоны.
- **`best_e010`** берётся из `stage3_choice.json`: `'a'` для `complex_a` и
  физических семейств, `'both'` для `complex_both`. Для физических семейств
  `c_mult` 30 ставится только если в своём эксперименте `best_e010_cm30` был
  лучше `cm1` по валидации; иначе `c_mult` 1.
- **Многоэтапные схемы** сохраняют структуру, длины фаз масштабируются: E017
  frozen — половина/половина; E018 послойная — Ns фаз + дообучка с lr/3,
  пропорционально.
- 5 участников × (1 + 2) прогона × 5 seeds = 75 прогонов. Валидация и тест
  каждые 5k, чекпоинты каждые 10k.
- **Контроль:** `complex_a` 20k const, 62.191 % ± 0.7 п.п. по seeds 17 и 29.

## Команды
```bash
bash experiments/E019_confirm_long_runs/run.sh control
bash experiments/E019_confirm_long_runs/run.sh main         # после summarize в E016, E017, E018
bash experiments/E019_confirm_long_runs/run.sh summarize
CONFIRM_ESTIMATE_FROM_SMOKE=1 bash experiments/E019_confirm_long_runs/run.sh estimate all
```
`CONFIRM_ESTIMATE_FROM_SMOKE=1` нужен только для оценки времени до появления
результатов E016–E018: участники берутся из smoke, длины остаются полными.
На настоящие прогоны флаг не влияет.

## Выходы
`results/confirm.csv` (по прогону и горизонту, с флагом «точка из кривой 200k»),
`results/confirm_summary.csv` (среднее, min/max, Q², плато, `y_inf`),
`results/confirm_choice.json`, `figures/E019_long_curves.png`.

## Ограничения
Участники выбраны по валидации коротких прогонов, поэтому длинные прогоны
подтверждают именно этих победителей. Один split, 30 train-файлов.
