# E046 — Фаза 2, архитектура A: Керр с памятью + внеосевые триплеты

**Вопрос.** Лучше ли при равных RM, чем одни триплеты и один Керр, связка «Керр с памятью (в первом порядке это осевые триплеты) + внеосевые триплеты (остаток IFWM)», и сколько внеосевых членов стоит оставлять?

**Правило (до запуска, черновик).** A побеждает, если при равных RM (у соперника RM ≤ 1.05 × RM A) её лучшая по валидации конфигурация лучше на тесте и лучших «только триплетов», и лучшего «только Керра» больше чем на 2 std по репликам; иначе — отрицательный результат как есть. Полностью — `config.json` → `rule_draft`.

**Модели** (`kerr_offaxis.py`): Керр — КИХ7 + фаза φ_k = Σ α_j |u_{k+j}|², N_c ∈ {7, 15, 31}; внеосевые члены — область T3 с m ≠ 0, n ≠ 0, M ∈ {3, 5, 8}. A1: Керр → триплеты; A2: триплеты → Керр; A3: параллельно; контроли: только триплеты T (T3 + КИХ7), только Керр K, Керр + T3 с осями (A3full, двойной счёт). Обучение: variable projection (α по L-BFGS на 4 файлах, C исключается ридж-решением) и по очереди (сначала Керр, потом ридж на остатке; A2 — наоборот); затем C в закрытой форме на всех 30 файлах, λ по валидации. Развёртки: K сильнейших внеосевых членов по |C|·rms и геометрический отсев |mn| ≤ K_th. Совместное дообучение Adam — следующий шаг, если A положительна. Аналога схемы в проверенных источниках не найдено (поиск неполный).

**Протокол.** 5 бутстреп-реплик файлов обучения; лучшие конфигурации каждой архитектуры — ещё на 3 разбиениях E023 (101, 202, 303).

**Команда.** `bash experiments/E046_kerr_offaxis/run.sh <стадия>`; стадии: main | splits | summarize | smoke.

**Результаты.** `results/a_summary.csv` (mean ± std), `a_verdicts.csv`, `a_splits.csv`; рисунки `figures/E046_gain_vs_offaxis_terms.png`, `E046_a_vs_controls_rm.png`.
