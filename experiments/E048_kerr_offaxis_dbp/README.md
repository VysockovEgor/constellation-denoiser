# E048 — Архитектура A при большей памяти и DBP + внеосевые триплеты

**Вопрос.** Догоняет ли архитектура A настроенный DBP при большей памяти (M = 11, 15; N_c = 31, 63), и помогают ли DBP внеосевые триплеты там, где осевые триплеты E038 дублировали его фазу Керра?

**Правило (до запуска, черновик).** A побеждает, как в E046, при разнице > 2 std над «только триплетами» и «только Керром» при равных RM. Внеосевые триплеты добавляют к DBP при ≥ 1 п.п. и непересекающихся интервалах (как E038). A лучше DBP + внеосевых на уровне RM при разнице > 2 std. Полностью — `config.json` → `rule_draft`.

**Цена Керра.** N_c — общее число отводов фазы (j = −(N_c − 1)/2 … (N_c − 1)/2), веса симметричны, различных (N_c + 1)/2. RM Керра = 4L + 2 + (N_c + 1)/2 + 4: при N_c = 31 — 50 RM, при N_c = 63 — 66 RM (exp — по таблице, как `macs_phys`).

**Части.** (1) Закрытая форма, как E046 (`e046_fit` с `TRIPLET_KERR_EXP=E048`): A1 (variable projection) и A3 (по очереди), контроли T и K, 5 реплик, лучшие — на 3 разбиениях E023. (2) DBP Ns 8 / 16 (рецепты F6 / F7, как E038) + K ∈ {0, 16, 32, 64, 128} сильнейших внеосевых членов закрытой формы M = 15; 5 seeds × 200k.

**Команда.** `bash experiments/E048_kerr_offaxis_dbp/run.sh <стадия>`; очередь — `bash scripts/remote.sh go e048 all`.

**Результаты.** `results/a_summary.csv`, `a_verdicts.csv`, `a_splits.csv`, `dbp_offaxis_summary.csv`, `dbp_offaxis_verdicts.csv`.
