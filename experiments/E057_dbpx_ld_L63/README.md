# E057 — DBP-X, Ns = 20: совместный МНК каскада (direct_ld) при L = 63

## Вопрос
В E054 ветка direct_ld считалась только при L = 31, 15, 7. При L = 31 она лучше прогрессивной обрезки: 97.86 ± 0.02 % против 96.80 ± 0.13 %.
Догоняет ли direct_ld при L = 63 прогрессивную обрезку при той же длине (99.07 %, 10 seeds, E054)? Иначе говоря, сохраняется ли преимущество совместного старта каскада, когда фильтр достаточно длинный?

## Что запускается
- Функция `e054_prune.run(ns=20, mode="direct_ld", target=63)` используется без изменений ([e057_ld63.py](../../src/constellation_denoiser/e057_ld63.py)).
- Старт:
  - физические отводы шага, обрезанные до 63;
  - 300 итераций L-BFGS по L_D Xiao (совместная подгонка каскада, сохраняется наименьший L_D);
  - α, знак и множитель — по выбору E050 start (валидация);
  - комплексное усиление — МНК по train.
- Обучение:
  - Adam 1e-3, 4 целых train-файла за итерацию со случайным циклическим сдвигом, MSE по всем символам;
  - 9 000 итераций — столько же, сколько прогрессивная ветка E054 тратит до L = 63;
  - чекпоинт — минимум MSE на валидации (оценка каждые 100 итераций).
- Seeds: 17, 29, 43, 57, 71. Контроль `complex_a` — как в E054.

## Правило (до запуска, `config.json` → `rule_draft`)
direct_ld при L = 63 (5 seeds) сравнивается с прогрессивной обрезкой E054 при L = 63 (10 seeds). Различие признаётся сигналом, если |разность| > 2 SE и > 2 std (правило E054). Иначе — «разница не доказана».

## Ограничения
- Одно расписание, без подбора; 5 seeds.
- Эталон взят из другого эксперимента (тот же код, те же данные, тот же выбор старта).
- Файлы циклические; один канал, одна поляризация, 1 отсчёт на символ.
- Конвенция RM не меняется (ждём ответа научрука): в сводке указаны обе.
