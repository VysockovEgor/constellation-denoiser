# E016 — Чисто физическая модель PhysKerr

## Вопрос
Сколько из ≈64 % снижения BER, которые дают комплексные MLP на 6–16 тысяч
умножений, даёт модель из 10–160 умножений на символ? Модель — КИХ-фильтр и
нелинейный фазовый сдвиг, зависящий от взвешенной суммы мощностей соседей, как
в цифровом обратном распространении (Sidelnikov et al., JLT 2021).

## Правило интерпретации (до запуска) — ЧЕРНОВИК
Статус: черновик, пользователь подтверждает его до первого запуска; после
просмотра результатов не меняется. Копия в `config.json` → `rule_draft`.

- «**Физика достаточна**». Среди конфигураций PhysKerr не дороже 10 % от 6 480
  (≤ 648 умножений, все ветки lr) берётся одна — с лучшей средней валидацией.
  Её среднее тестовое снижение BER по 5 seeds должно быть не хуже `complex_a`
  (const 1e-3, 20k, те же 5 seeds) более чем на 2 п.п.
- «**Физика полезна**» (структура даёт прирост). Эталон — «линейный КИХ + один
  Керр»: R = 1, L = 31, тот же sym, та же ветка lr. Среди конфигураций с R > 1,
  которые не дороже эталона, по валидации выбирается одна. Она должна быть
  лучше эталона на тесте не менее чем на 1 п.п. и больше разброса seeds.
- Иначе — «не доказано».

Метрика — тест в точке лучшей валидации (`test_reduction_valbest_select`,
замер каждые 1000 шагов) и Q²-прирост в той же точке. Выбор только по
валидации (`best_val_reduction`). Разброс seeds — размах (max − min); берётся
больший из двух сравниваемых групп.

## Модель
`src/constellation_denoiser/phys_models.py`, `PhysDBP` с одним шагом:

    u = F(z)  (комплексный КИХ длины L внутри окна, L = 1 — без КИХ)
    y = u_c · exp(−i · Σ_{j=−r..r} α_j · |u_{c+j}|²),   r = (R − 1)/2

- Окно 31 символ, как в E010–E014; выход — центральный символ.
- КИХ стартует с единичного импульса, α = 0: на старте модель тождественна.
- Опция `sym`: α_j = α_{−j} и h_j = h_{−j} (комплексные отводы).
- Лосс — complex MSE, как у `complex_a`.
- Фильтр и свёртка мощности реализованы умножением на ленточную (тёплицеву)
  матрицу внутри окна с нулевым дополнением у краёв. Совпадение с `conv1d`
  проверено (отличие ~2e-7); так в 5–7 раз быстрее на CPU.

## Подсчёт умножений: `macs_phys(R, L, sym)` (`model_zoo.py`)
Потоковая реализация: каждый принятый символ фильтруется один раз и
переиспользуется соседними выходами.

| часть | без симметрии | с симметрией |
|---|---|---|
| КИХ длины L (L = 1: нет КИХ, 0) | 4·L | 2·(L + 1) |
| \|u\|² | 2 | 2 |
| свёртка мощности (R коэффициентов) | R | (R + 1)/2 |
| exp(−iφ) из таблицы | 0 | 0 |
| поворот (комплексное умножение) | 4 | 4 |

С симметрией нелинейный слой стоит `0.5·(R + 1) + 6`, а в статье указано
`0.25·(R + 1) + 6`. Разница в множителе свёртки, подгонкой её не убирал.
Вероятная причина (PDF статьи нет, проверить не удалось): статья считает
двухполяризационный сигнал, где одна свёртка суммарной мощности |x|² + |y|²
общая для двух поляризаций. Тогда на одну поляризацию приходится
0.25·(R + 1), а 2 (своя |z|²) + 4 (поворот) = 6. У нас одна поляризация
(`data/README.md`, 4 столбца на символ), поэтому свёртку делить не на что.

Примеры: R=7, L=1, sym — 10; R=7, L=31, sym — 74; R=31, L=31, без симметрии —
161. Для сравнения: `complex_a` после слияния — 6 480.

## Сетка
- R ∈ {1, 3, 7, 11, 21, 31}; L ∈ {1, 7, 31}; sym ∈ {нет, да}. Пара R=1, L=1
  при sym да/нет — одна и та же модель, она обучается один раз: 35 конфигураций.
- Нижняя граница — КИХ без нелинейности: L=31, R=0, sym да/нет.
- Ветки lr: `const_1e-3`; `best_e010_cm1` и `best_e010_cm30` — конфигурация
  E010 stage3 для архитектуры `a` (`stage3_choice.json`: cosine_to_zero, пик
  3e-3, warmup 0) с `c_mult` 1 или 30 для α. Без файла ветки `best_e010`
  пропускаются.
- 20k шагов, seeds 17, 29, 43, 57, 71, 30 train-файлов, валидация каждые 1000.
- Прогонов: 37 × 3 × 5 = 555 (стадия `main`) + 5 (`control`).
- **Контроль:** `complex_a`, const 1e-3, 20k, 5 seeds. Допуск — 62.191 % ±
  0.7 п.п. по среднему seeds 17 и 29. Если контроль не прошёл, `main` не
  запускается.

**Наблюдение smoke (300 шагов, не вывод).** Ветка `best_e010_cm30` даёт для
α lr 3e-3 × 30 = 0.09. Часть конфигураций при этом схлопывается до BER ≈ 0.5,
хотя NaN нет. На графике такие точки отмечены треугольником на нижней
границе; отбор по валидации их не выбирает.

## Ограничения
- Окно 31 с нулевым дополнением: при L = 31 и большом R крайние соседи
  фильтруются по неполному окну. Потоковая реализация с тем же подсчётом
  умножений этого ограничения не имеет, так что оценка консервативна.
- Одна поляризация, один split, 30 train-файлов.
- Q² в точке лучшей валидации считается из BER = raw·(1 − reduction/100). Это
  точная арифметика: reduction вычислен из этого BER.
