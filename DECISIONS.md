# Решения E024–E033 (где план расходится с кодом или данными)

1. Новый код — модулями (`models_e024`, `losses_new`, `recipes`, `grids_e024`, `gate`, `pareto_v2`, `triplets`); в старых добавлены только точки подключения с прежним поведением по умолчанию: `runner` (параметр задачи `loss`, по умолчанию MSE), `model_zoo` (новые виды моделей), `grids` (регистрация `grids_e024`). `recipes.py` лежит в пакете `src/constellation_denoiser/`, `recipes.json` — в `results/`.
2. Размер батча не настраивается (`runner.BATCH_SIZE = 1024`); weight decay > 0 — через AdamW (Adam в `lr_schedules` его не применяет); у физики `c_mult` — множитель lr коэффициентов α.
3. Кодовая проверка E025 «F2 с ref_e010best = 66.0 ± 0.7»: якорь измерен на `complex_a` (E019), поэтому проверяется `complex_a` cm30 200k, seeds 17, 29, цель 66.253 ± 0.7.
4. Kerr-коэффициент c в текущем коде один на слой (не на нейрон); `kerr_c_fixed` берёт медиану обученных c той же ширины и длины, поэтому стадии `*_fixed` идут после обычных.
5. «DBP + MLP-голова» (E028) и «front-end» (E029) — параллельная сумма, как гибрид E017/E020 (`phys_plus_mlp`), а не каскад.
6. Оценки валидации и теста — каждые max(500, шагов/40) шагов (E032 — 20k); выбор между стадиями — средняя `best_val_reduction`, разошедшиеся исключены.
7. Автостоп: в стадиях поиска (E025 S1/S2, E026 grid, E027 S1/S2, E030 S1) считаются только упавшие прогоны — расхождение при большом lr там ожидаемый результат; память < 16 ГБ — останов после 30 мин ожидания.
